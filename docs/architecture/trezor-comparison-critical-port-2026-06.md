# Trezor (STM32U5 / T3W1) → PQSigner — Critical Port Pass (Extending `trezor-comparison.md`)

**Date:** 2026-06-30
**Scope:** Fresh critical pass against Trezor HEAD `a0fe1eccc2` vs PQSigner `master`. This **extends** `docs/architecture/trezor-comparison.md` (2026-04-24 / 05-19) — it does not re-derive what that doc already covers soundly. It surfaces (a) genuinely new ports, (b) challenges to existing-doc verdicts that aged badly or were too hasty, (c) refreshes for moved Trezor code, and (d) a "considered & rejected" ledger so the same ideas don't resurface next quarter.

Every candidate below was adversarially verified against PQSigner's real files, threat model, and deliberate-design constraints. Calibration note up front: **the single strongest finding is only "med" impact.** There is no headline break here — PQSigner's signing-path FI, dual-SE split, and on-device-decode trusted display are already strong. The value is in cheap defense-in-depth that closes glitch/fault windows, plus correcting stale verdicts in the comparison doc itself.

> **Method / provenance.** Produced by a 12-dimension `compare → adversarial-verify → synthesize` agent pass (each candidate checked against the real PQSigner file, not CLAUDE.md, which lags). The top three findings (rr-1, sca-3, tz-2) were additionally hand-verified against source (`main.rs:3711/3791/3830/3904` has no fault handler; `crypto.rs` passes the same `&shuffle` to both signs; `sau.rs:432` ends at `SAU.ctrl.write(1)` with no lock bit). **C-1 (secmon) and the supply-chain row were re-run with dedicated deep agents after synthesis and materially correct the first-pass framing** — see the note in §C-1. Trezor is pinned to the STM32U5 / T3-series paths (architectural twin = T3W1 = STM32U5A9 + OPTIGA Trust M).

## TL;DR — highest-value portable improvements (ranked)

1. **Route CPU faults to zeroize+reset** — `med` / `S`. No `HardFault`/`SecureFault` handler exists (`main.rs` has only SysTick/DefaultHandler/PendSV); a glitch-induced CPU fault during the signing window freezes the device with `master_secret`+entropy live in S-SRAM. Add a `HardFault` handler → `zeroize_sensitive_state()` + `SCB::sys_reset()`. **Real-gap-closing.** *(rr-1)*
2. **Lock SAU+GTZC1+AIRCR after configuring them** — `med` / `S`. `sau::init()` ends at `SAU.ctrl.write(1)`; the programmed SAU regions + TZSC SECCFGR stay writable forever. One write of `CSLCKR.LOCKSAU|LOCKSVTAIRCR` + `TZSC1.CR.LCK` removes the target. Universal Trezor U5 practice. **Defense-in-depth, ~10 LOC.** *(tz-2)*
3. **Give the FI double-compute an independent shuffle seed** — `low-med` / `S`. `crypto.rs:170/173` pass the *same* `&shuffle` to both mandatory signs, donating two perfectly-aligned DPA traces per signature (a free ~√2 denoise) on the exact alignment the F-16 shuffle exists to deny. ~3 lines; provably FI-safe (output is shuffle-invariant, tested). **Corrects a wrong rationale in non-negotiable signing code.** *(sca-3)*
4. **Extend the golden UI-hash gate beyond value-transfer** — `med` / `M`. `golden.rs::screens()` renders only `value_transfer` (5 frames); the attacker-relevant decode-and-render screens (Safe/CoW/ERC-7730/EIP-1271) — the WYSIWYS boundary — have semantic tests but no pixel-hash gate. CI is already wired. **Real-gap-closing on the core security boundary.** *(te-2)*
5. **Secure the RCC/PWR/SYSCFG domain controllers** — `med` / `S`. `sau.rs` writes only the TZSC per-peripheral SECCFGR; `RCC->SECCFGR`/`PWR->SECCFGR`/`SYSCFG->SECCFGR` sit at NS reset default, letting a compromised NS reconfigure the clock tree the S-world runs on and touch the backup domain where the BHK latches. **Defense-in-depth.** *(tz-3)*
6. **FSBL boot-time option-byte integrity gate** — `med` / `M`. The FSBL is the WRP1A-locked trust root yet never reads back `OPTR`/`WRP1AR`/`SECWM` to confirm RDP-2/TZEN/WRP-covers-FSBL are actually in force. Read-only verifier → halt+tamper-screen on mismatch. **Trust-root self-attestation, not exploit closure.** *(tz-1 + sh-1, merged)*
7. **Defer the OTP rollback-floor bump to first-confirmed-boot** — `med` / `L`. `cmd_fw_commit.rs:268` bumps the floor at install, eliminating the old slot as a try-once revert target; a validly-signed-but-runtime-hanging upgrade is an unrecoverable brick. **Availability-only (not attacker-triggerable), but non-trivial to fix correctly.** *(boot-1)*
8. **Cap how long `handler_is_busy()` may feed the IWDG** — `med` / `M`. The watchdog's liveness model means a wedged handler feeds it forever — and the same `handler_busy` gate also suppresses the 120 s idle-wipe, so one hang defeats both backstops. Self-acknowledged hole in `iwdg.rs:38-40`. **Defense-in-depth.** *(rr-2)*

Plus the most important *critical* point, which is **not** a cheap port and where the first-pass framing was itself wrong: Trezor shipped `secmon`, but a deep re-check shows it is a *separate signed image that is the sole secure-world occupant and pushes all decode/render to a non-secure kernel, signing whatever digest NS hands it* — i.e. it optimizes key-confidentiality-vs-NS-bugs by **trusting NS for what-you-sign**, the exact "blind-digest oracle" PQSigner refuses. A full `secmon` port should be **declined on principle**; the only defensible transferable increment is an MPU-lite fence (the ERC-7730 walker and other native decoders run S-unprivileged, key+SAES privileged). See Challenges §C-1 for the corrected analysis.

## Headline findings (the actionable ports)

### rr-1 — Route CPU faults (HardFault et al.) to zeroize+reset
- **Trezor:** `core/embed/sys/task/stm32/systask.c:771-849` routes HardFault/MemManage/BusFault/UsageFault/SecureFault/GTZC → `systask_exit_fault` → `reboot_with_rsod`.
- **PQSigner (verified):** `secure/src/main.rs` defines only `SysTick` (:3711), `DefaultHandler` (:3791), `PendSV` (:3830), and a zeroizing `#[panic_handler]` (:3904). **There is no HardFault-family handler**, so a CPU fault lands in `cortex-m-rt`'s default `loop{}` with secrets intact; the zeroizing path is reachable only via Rust `panic!()`. `iwdg` is *not* in `mode-production` (`secure/Cargo.toml:151`), so a shipping build may have no watchdog backstop either.
- **Adjusted change (PORT-with-correction):** add `#[cortex_m_rt::exception] unsafe fn HardFault(_) -> !` under `cfg(all(not(test), feature="stm32u585"))` calling `nsc::zeroize_sensitive_state()` then `cortex_m::peripheral::SCB::sys_reset()` — **NOT** `tzic::trigger_intrusion_wipe()`. The candidate's `trigger_intrusion_wipe` arms page-125, which on next boot runs `factory_reset_admin` (`main.rs:1438`) — a destructive dual-SE wipe; routing *every* induced fault there turns a single glitch into a wallet-brick/DoS. PQSigner stores **no seed in flash** (dual-SE XOR, re-derived after PIN), so a plain reset already closes the SRAM-extraction window via FSBL re-verify. This mirrors `docs/security/brownout-hardening.md` Stage-2 NMI shape exactly. Granular `SHCSR.{MEM,BUS,USG,SECURE}FAULTENA` enables are diagnostics-only (faults escalate to HardFault regardless) → **the security-critical fix is just the HardFault handler, effort S**; the tamper screen + granular handlers are an optional M follow-up. Reserve the destructive SE-wipe for confirmed TAMP/GTZC tamper.
- **Threat note:** Genuine and currently unmitigated for the immediate window. CPU-fault-as-glitch-symptom is PQSigner's headline threat (the same Masaryk-U STM32U5 76%-PIN-glitch result cited in the brownout doc). The only existing backstop is the (non-production) IWDG ~2 s window. **This is the sharpest finding in the pass.**

### tz-2 — Lock SAU + GTZC1 + AIRCR after configuring them
- **Trezor:** `core/embed/sec/trustzone/stm32u5/tz_init.c:410-415` sets `SYSCFG->CSLCKR |= LOCKSAU|LOCKSVTAIRCR` + `GTZC_TZSC1->CR |= LCK`; `:132-145` sets `AIRCR.PRIS` always, `SYSRESETREQS` under `#if PRODUCTION`, clears `BFHFNMINS`.
- **PQSigner (verified):** `sau::configure_gtzc()` ends at the SECCFGR write + readback self-check (`:354-366`); `init()` ends at `SAU.ctrl.write(1)` (`:432`). No lock bit is ever set — the fully-programmed SAU RLARs and TZSC SECCFGR bits stay writable for the rest of boot/runtime.
- **Adjusted change (ADAPT):** at the end of `sau::init()` (after all four SAU regions + GTZC are programmed), gate on `stm32u585`: (1) `SYSCFG_CSLCKR |= LOCKSAU | LOCKSVTAIRCR`; (2) `GTZC1_TZSC->CR |= LCK`. Do **not** touch `GTZC2_TZSC->CR` (unconfigured — the tracked TAMP/GTZC2 follow-up). Set `AIRCR.PRIS` + clear `BFHFNMINS` unconditionally, but gate `SYSRESETREQS` behind `#[cfg(feature="mode-production")]` so bench keeps the NS-initiated `cc_open_then_reset` USB-C warm-reset. Funnel writes through `hw::mmio::Reg32`; add a write-readback `debug_assert`. Caveat to document: `LOCKSVTAIRCR` freezes the AIRCR *security-config* bits, not the `SYSRESETREQ` trigger.
- **Threat note:** `med`/defense-in-depth. TZSC SECCFGR/SAU are only writable from S-world, so the realistic vector is a fault flip or a stray secure-world write (re-classify secure SRAM as NS, mark SAES NS) — at a layer *below* the signing-redundancy FI defense. Cheap, reset-scoped, aligned with Trezor's universal U5 practice.

### sca-3 — Independent shuffle seed for the FI double-compute
- **Trezor:** `core/embed/sec/random_delays/stm32/random_delays.c:45-51` — principle: protective randomness drawn fresh per operation, never reused (conceptual anchor, not a direct port; Trezor has no SPHINCS+ double-compute).
- **PQSigner (verified):** `crypto.rs:170` `sign_a` and `:173` `sign_b` use the **identical `&shuffle`**. The F-16 shuffle only randomizes computation *order* and produces byte-identical output for any seed (proven by `tests/shuffle_byte_equality.rs`). Reusing the seed makes both passes traverse WOTS/FORS in the same order → two trivially alignable traces of the same secret computation. The in-code comment (`crypto.rs:144-145`) frames divergent seeds as a con to the byte-equality gate — the SCA benefit is inverted.
- **Change (PORT):** draw a second independent shuffle seed from `rng_strong` for `sign_b`; zeroize both. Output is shuffle-invariant (tested), so `ct_eq` and verify-before-release still hold and a grafting fault must still produce *identical faulted output in both passes* to slip through — FI hardness unchanged, FI neutral-to-better. Correct the comment.
- **Threat note:** Impact is a bounded constant factor (~2× attacker trace efficiency on a profiled-DPA premise), not a break — hence `low-med`, downgraded from the candidate's `med`. But it directly undermines a deliberately-engineered countermeasure at ~3 LOC. **Best value-per-effort in the pass.**

### te-2 — Extend the golden frame-hash UI gate to the security-critical screens
- **Trezor:** `tests/ui_tests/common.py` — golden screenshot-hash gate across all flows.
- **PQSigner (verified):** `secure/src/ui/golden.rs::screens()` returns `[Eip1559Tx; 5]` and renders only `value_transfer::render_pages` (`:67`). `golden.rs:12-14` flags ERC-20/Safe/CoW extension as the explicit TODO. The Safe/CoW/ERC-7730/EIP-1271 renderers have byte-binding *semantic* tests (`secure/src/display_under_test/{cowswap,safe_display,erc7730}_render_pure_tests.rs`) but **no pixel-level golden fixture**. `nightly.yml`'s `ui-golden-render` job already runs the gate.
- **Change (ADAPT):** refactor `render_golden_and_halt` to drive each production page builder (`safe_display`, `cowswap_display::append_order_body_pages`, Safe-wrapped CoW `setPreSignature`, `erc7730` descriptor pages, `erc20_known`, `eip1271`), reusing the input fixtures already built in the `display_under_test` pure-test modules. Each builder's pages flow through `render_capture_pages`, appending `[UI-FP]` frames; regenerate `tests/ui_golden_render_fixtures.json` via `make ui-golden-render-bless`. No CI change.
- **Threat note:** Squarely on the WYSIWYS boundary. On-device decode defeats host data-swap, but a layout/truncation/unit/digit-grouping regression in these renderers can silently misrepresent intent — exactly what byte-binding tests don't catch. `med`, real-gap-closing. **Priority bumped by the recent ERC-7730 churn:** the historical C1/C2/C3 experiment was tightened on 2026-07-10 to exact C1-only framing (C2/C3 retired), two WYSIWYS holes were fixed in the walker/compiler, and Aave clear-signing now flows through this ERC-7730 render path (post-`b8a2e59b`, replacing the removed ZK path) — so the un-pixel-gated screens are carrying real traffic and changing fast. The ERC-7730 descriptor pages should be the *first* builder added to the golden gate, not the last. Also refresh doc §2.3 (it still claims "no UI regression coverage" and cites SSD1306 GDDRAM bytes — OLED was removed 2026-06-30).

### tz-3 — Secure the RCC / PWR / SYSCFG domain controllers
- **Trezor:** `tz_init.c:296-326` writes all three: `SYSCFG->SECCFGR` (FPU/CLASSB/SYSCFGSEC), `RCC->SECCFGR` (full clock tree incl. PLL/SYSCLK/sources), `PWR->SECCFGR` (WUP/LPM/VDM/**VB**/APC) — dead code if TZEN secured them by default, which is the strongest evidence they default NS.
- **PQSigner (verified):** `sau.rs` writes only GTZC1 `TZSC_SECCFGR1/2/3` + MPCBB; `grep -rni seccfgr secure/` confirms RCC/PWR/SYSCFG SECCFGR are never written.
- **Change (ADAPT):** in `configure_gtzc()` (or a sibling), program: (1) `RCC_SECCFGR` — secure the **full** clock tree + `RCC_PRIVCFGR SPRIV` (PQSigner needs **no NS display-PLL carve-out** like Trezor's PLL3=NS, because the NV3007 is SPI-clocked off a secure prescaler and NS never reconfigures clocks at runtime — `nonsecure/src/usb/mod.rs:42` "clocks already configured by the secure world"); (2) `PWR_SECCFGR` incl. `VBSEC` (guards the backup domain where the BHK latches in `TAMP_BKP0R..7R`); (3) `SYSCFG_SECCFGR` (FPU/CLASSB/SYSCFGSEC). Fold the tz-2 lock over these. **Caveat:** securing RCC will fault the debug-only NS pre-USB RCC dump at `nonsecure/src/main.rs:153-158` — acceptable (debug-log-gated, never ships); verify it's compiled out. Add a readback self-check + pure-test mirroring `main_sau_pure_tests.rs`.
- **Threat note:** `med`/defense-in-depth — *not* a live mid-sign glitch (single core, all NVIC IRQs secure-by-default, NS cannot preempt a signature). It's "persistent NS clock/power reconfig + backup-domain attack surface." Cheap; aligns with Trezor's "secure owns the clock tree" posture. (Also listed in Challenges as it widens §1.1's allowlist verdict.)

### tz-1 + sh-1 (merged) — FSBL boot-time option-byte / secure-config integrity gate
- **Trezor:** `core/embed/sec/option_bytes/stm32u5/option_bytes.c:124-264` (`flash_check_option_bytes`) checks `OPTR`/`SECBOOTADD0R`/`WRP1AR`/`SECWM1-2R`/OEM-keys on every boot; boardloader `main.c:321-336` → `secret_safety_erase` on mismatch.
- **PQSigner (verified):** option bytes are set by an out-of-band `STM32_Programmer_CLI` step (`secure/src/factory_provisioning.rs:18-19`); `grep` of `fsbl/`, `secure/src/main.rs`, `sau.rs`, `hw/flash.rs` finds **no `FLASH_OPTR` read anywhere**. The FSBL header (`fsbl/src/main.rs:12`) asserts "Production RDP-2 prevents SWD recovery" — an unverified assumption.
- **Change (ADAPT — strip Trezor's write/`OBL_LAUNCH` half entirely):** add `fsbl/src/optbytes.rs`, called from `main.rs` *before* `render::render_fingerprint`/branch (placement is load-bearing: the WRP1A-locked anchor must host the check so a tampered slot can't patch it). Read `OPTR`/`WRP1AR`/`SECWM1R1-R2`+`SECWM2R1-R2`/`SECBOOTADD0R` + NSSR OEM-lock bits; assert TZEN set, RDP at expected level, WRP1A actually covers FSBL pages 0..3 (unlock clear), SECWM matches the secure-flash boundary, OEMxLOCK==0. Gate the readbacks through `fsbl/src/fi.rs` sentinels. On any mismatch: **do not branch, do not SE-wipe** (FSBL has no SE driver; SE secrets self-invalidate via DHUK) — render a distinct fault code on the NV3007 (`fsbl/src/nv3007.rs`) and `halt()`. Parameterize expected constants per build profile (production WRP-locked vs bench WRP-default), mirroring Trezor's `#if PRODUCTION`. Optional S-world mirror after SAU/GTZC setup.
- **Threat note:** `med`/defense-in-depth + tamper-evidence, **not** a plugged confidentiality hole. Confidentiality is bound elsewhere: U5 mass-erases on RDP regression, SE-pairing secrets self-invalidate (per-die DHUK → ST RDP0 constant), no seed in MCU flash. Real residual = a glitched/partial OB edit that weakens WRP1A (exposing the FSBL anchor to reflash) or shifts SECWM without tripping the full mass-erase, plus auditability of a manual factory step. Against an active attacker the check is partly circular (if WRP1A is unset the slot is reflashable and the check patchable) — say so honestly.

### boot-1 — Defer the OTP anti-rollback-floor bump to first-confirmed-boot
- **Trezor:** `version_check.c:41-46` `ensure_firmware_min_version` bumped at boot (in the bootloader pre-jump, `main.c:479`), not at install.
- **PQSigner (verified):** `cmd_fw_commit.rs:268` bumps `otp::bump_to(new_version-1)` at install AND sets `boot_state.active_slot=new` (`:174-178, :205-212`). FSBL `filter_valid` runs `verify_rollback(floor)` on both slots (`fsbl/src/main.rs:91,160-166`), so a cross-version old slot is eliminated; `pick_slot`'s try-once revert (`:208-214`, fires when `winner_flag==TRIED && active_slot==winner_slot`) then has no target. A validly-signed image that passes FSBL static checks but hangs at runtime reboots into the only remaining (broken) candidate forever — unrecoverable under RDP-2 + WRP1A. The advertised confirm-alive writer (`boot_state.rs:8,:127`) is vaporware (`boot_state::write` only in `cmd_fw_commit`).
- **Change (PORT-with-correction — THREE coupled edits, not two):** the eager bump is currently *load-bearing* (it eliminates the old slot so the new TRIED slot is the only candidate); removing it alone makes the new slot's first boot see `TRIED + active_slot==new` and instantly revert. So: (1) at commit, leave `boot_state.active_slot` pointing at the **old** slot (record "about to try new" via the manifest TRIED flag only); (2) build the confirm-alive writer `boot_state.rs` already advertises — on first successful `gated_unlock` (`cmd_request_unlock.rs`) or NS handoff, rewrite the running slot's manifest `TRY_ONCE_TRIED→COMMITTED`, advance `active_slot→new`, **then** `otp::bump_to(running_version-1)`, FI-hardened to match `bump_to`'s double-read + `check_true_into_sentinel`; (3) remove the `otp::bump_to` from `cmd_fw_commit.rs:268`. Floor stays strictly monotonic — it advances one boot later, on confirmation. Add a host test (old slot survives `verify_rollback` after commit-but-before-confirm) + an FSBL `pick_slot` hang-loop-revert test. **Note:** Trezor bumps in the bootloader pre-jump; PQSigner's FSBL is WRP1A-immutable/read-only on OTP, so deferring into the firmware confirm-alive path is the correct PQSigner layer.
- **Threat note:** **Availability-only, not attacker-triggerable** — an adversary can't sign firmware, the seed is dual-SE XOR + 24-word recoverable on a replacement. But it's an unrecoverable brick with no in-field reflash, and PQSigner already invests in this class (`docs/security/vulns/VULN-fwcommit-otp-before-commit-brick.md` handled only the *power-loss* sibling, which deliberately did NOT defer the bump). `med`, but `L` effort because the try-once machinery is half-built.

### rr-2 — Cap how long `handler_is_busy()` may feed the IWDG
- **Trezor:** `core/embed/sec/iwdg/stm32/iwdg.c:28` — flat hardware time-bound, no progress-feed concept (so there's nothing to literally port; PQSigner's liveness optimization created the hole).
- **PQSigner (verified):** `iwdg.rs:212` kicks while `handler_busy`; the module doc itself flags the residual at `:38-40` — a handler spinning forever with interrupts enabled + its `HandlerGuard` held feeds the watchdog forever. **Worse than stated:** the same `handler_busy` gate also guards the 120 s idle-wipe (`main_sau_pure_tests.rs:993` pins `&& !nsc::handler_is_busy()`), so a wedged handler defeats *both* the IWDG and the SRAM zeroize.
- **Change (ADAPT):** add `static mut BUSY_TICKS: u32` + `const MAX_BUSY_TICKS` in `iwdg.rs`. Treat the two progress signals asymmetrically: NS-heartbeat advance resets `STALL_TICKS` and kicks (unchanged); for the `handler_busy` branch, increment `BUSY_TICKS` per consecutive busy tick, reset to 0 when `handler_busy` goes false (a guard drop = liveness), and only kick while `BUSY_TICKS < MAX_BUSY_TICKS`. A local tick counter avoids plumbing a timestamp from `nsc`. Set the cap generously above the worst *legit* continuous-busy window — the binding constraint is a full `CMD_SIGN_USEROP_BATCH` (per-UserOp keygen + 2 FI-double-compute signs each), **not** a single first-sign (~3 s); measure on HW and set ~2-3× (likely 20-30 s). Add a host pure-test pinning the source invariant.
- **Threat note:** `med`/defense-in-depth — needs a latent unbounded-loop bug in a secure handler (parsers are bounded/Kani-checked, so reachability is low today). The point of a watchdog is to survive the bug you didn't find; this restores Trezor's "bites regardless" property. The `BUSY_TICKS` cap is the single backstop for both the IWDG and the idle-wipe.

### te-3 — SE-genuineness gate at factory provisioning
- **Trezor:** `core/embed/projects/prodtest/cmd/prodtest_optiga.c:353` `check_device_cert_chain` — OPTIGA device key signs a challenge (`optiga_calc_sign`) + X.509 chain verified to the Infineon CA, gating the irreversible `OID_CERT_DEV` write.
- **PQSigner (verified):** `secure/src/factory_provisioning.rs` has no genuineness step before it self-generates secrets and ratchets the chip into a locked state.
- **Change (ADAPT — tightly scoped):** (1) put the classical ECDSA-P256 verify + minimal DER/X.509 chain-walk **behind `#[cfg(feature="factory-provisioning")]` only**, so it never links into the wallet firmware (invariant #5 governs the *wallet* signer; the factory image is a separate single-purpose binary that already does irreversible OTP/LcsO work). (2) Add a feature-gated carve-out to the forbidden-classical-substring guards (`secure_crypto_glue_under_test/pure_tests.rs:1155-1157,1568` ban `p256::`/`ecdsa::`), keeping the guard hard for the shipping image. (3) Insert a fail-closed step in `run_and_halt` **before** the LcsO=Op ratchet / lockdown / OTP burn: read the OPTIGA Infineon device cert (E0E0/E0F0 chain), challenge the device key to sign a fresh nonce + verify against the cert + chain to a pinned Infineon CA root; mirror with the SE050 NXP birth-attestation against a pinned NXP root.
- **Threat note:** `med`, anti-counterfeit/supply-chain defense-in-depth — **not** a seed-secrecy fix (dual-SE XOR already bounds single-chip exposure) and explicitly **not** "closes S-2" (trust-anchor ownership is separately tracked in `reset.rs`/`lockdown_ta_pool`). Residual honesty: catches a counterfeit/emulated part entering a *trusted* factory line; a compromised line that re-flashes the factory image can patch the gate out. Distinct from §2.2 (symmetric handshake — a counterfeit chip holding our own PBS would PASS that round-trip) and from §5/line-441 (host-facing runtime ED25519 attestation, lifecycle-disjoint).

### Smaller ports (med-to-low, mostly cheap)
- **td-1 — chunk on-screen hex addresses into 4-char groups** (`med`/`M`). `primitives.rs:265-294` `write_addr_full` packs dense unseparated hex. Scope to `write_addr_full` only (leave `write_addr_full_or_name`'s name-anchored row alone); emit space-separated 4-char groups, equal weight (never first/last highlighting). Residual is real **only on the unknown-recipient path** (known addrs carry the Merkle-verified `+name` anchor, and PQSigner already shows full 40-hex). `M` because the fixed 16-col grid forces re-auditing per-renderer page-count constants + the `seen_last` gate when the block grows 3→4 rows; if a 4th row can't be accommodated cleanly, chunk within 3 rows (8/8/4).
- **td-2 — full 32-byte calldata hash on blind-sign** (`low`/`S`). `primitives.rs:597-619` `write_calldata_hash_rows` shows only 13 of 32 bytes — the one anchor on the no-decode path, contradicting the module's own full-address policy. Render full hash across two pages or a label-less 4-row page; bump `blind_sign.rs` page count and re-verify the confirm gate. Honest: forging 13 shown bytes is ~2^104 (infeasible), so consistency/defense-in-depth, not a break. The candidate's one-page layout is wrong (32 B = 64 hex > 48 hex/3-row page) — needs a real layout/budget adjustment.
- **td-3 — page-position counter on confirm** (`low`/`S`). Add a "p/n" footer indicator in `confirm.rs::render_page`. **Drop** the candidate's hold-progress-bar + rollback: `track_hold` already re-samples every 5 ms over 500 ms (`buttons.rs:267-292`), so the FI false-confirm motive is moot, and the `seen_last` scroll gate already enforces the scroll-then-confirm contract. Only the near-free counter is worth it.
- **se-3 — read the OPTIGA Security Event Counter (0xE0C5) at unlock** (`low`/`S`). Add `apdu::read_sec()` over the existing shielded connection; treat strictly **advisory** (log + surface elevated reading on the NV3007). **Do NOT wire into `tamp-wipe`** — SEC bumps on ordinary wrong-PIN/integrity events and decays ~1/`T_MAX_MS`, so auto-wiping would brick legit users and the desolder threat is already hard-bounded by the E120 LUC. ## Challenges to the existing comparison doc

This is the most important "be critical" section. Four verdicts in `trezor-comparison.md` have aged into being stale or too hasty, and one architectural stance is now contradicted by Trezor's own move on the identical silicon.

### C-1 (NEW, the big one — re-verified, first-pass framing corrected) — the "small, audited, monolithic S-world" stance vs Trezor's `secmon`

> **Correction note.** The synthesis first wrote this as "Trezor shipped a privileged supervisor *inside the secure side* on PQSigner's *exact* silicon — a peer rejection of monolithic-S." A dedicated deep re-check (file-cited below) shows **all three of those claims are imprecise or wrong**. The corrected analysis is more interesting and more honest: `secmon` and PQSigner's flat-S optimize *opposed* threats, and a full port would import the one thing PQSigner exists to forbid.

- **Prior doc posture:** §3.2 / §8.2 (line 601 "not needed today") / §8.5 repeatedly wave off intra-secure isolation gaps with "the whole S-world image is small and audited." No dimension ever challenged the monolithic-secure-world assumption — that part of the challenge stands.

- **What `secmon` actually is (verified).** It is **not** an S-priv/S-unpriv tier inside one image. It is a *separate, separately-signed* secure image with its own vendor header + `headertool` signature pass and CMSE implib (`SConscript.secmon:331-333,398-442`, `linker/stm32u58/secmon.ld`). At runtime it is the **sole secure-world occupant**: `main()` → `tz_init()` → `drivers_init()` → `jump_to_vectbl_ns(KERNEL_START)` (`secmon/main.c:155-166`) — it hands the kernel + app off to the **non-secure** side. SRAM/flash are configured secure *and* privileged uniformly (`tz_init.c:161-162,200-209`); there is no second privilege tier. The boundary is the ordinary SAU + GTZC S/NS line, reached via `smcall` whose `__verified` wrappers `probe_read/write_access`-validate NS pointers (`smcall_dispatch.c:61-116`, `smcall_verifiers.c:36-90`) — the same shape as PQSigner's own NSC `NsPtr` discipline.

- **The load-bearing reframe.** `secmon`'s entire sign surface is **digest-in / sig-out** — `optiga_sign__verified(index, digest, …)` (`smcall_verifiers.h:61`). It contains **no** transaction decoder, ABI parser, or display renderer; the NS coreapp/MicroPython decodes, renders, and hands `secmon` a finished digest to **sign blind**. So Trezor's WYSIWYS TCB is the *signed NS firmware*. **PQSigner explicitly forbids exactly this** (CLAUDE.md: bare-signing a companion-chosen 32-byte value is a "UserOp-forgery oracle"; the entire on-device-decode trusted-display model exists to deny it). `secmon` therefore closes *key-confidentiality-vs-NS-memory-bugs* while *trusting NS for what-you-sign*; PQSigner's flat-S closes *what-you-sign integrity* by co-locating decode+render+sign, *accepting* a parser-next-to-key blast radius. **They optimize different, partly opposed threats — `secmon` is not strictly better.**

- **Silicon (corrected).** `secmon` builds **only** for T3W1/D002 (`SConscript.secmon:256-263`) = `mcu="STM32U5G9xx"`. The U585-class Trezors (T3T1/T3B1) ship the **empty `secmon.bin` stub**. So "shipped on PQSigner's exact silicon" is **wrong** — it's a sibling U5 die (U5G9 vs U585). The `#if STM32U5A9xx || STM32U5G9xx` + `linker/stm32u58/` paths show the design *is* portable to U585, so the architectural point survives, but the "peer is doing it on our exact part" pressure does not.

- **PQSigner today (verified flat).** Grep of `secure/src` returns **zero** `MPU` / `PRIVDEFENA` / `CONTROL.nPRIV` uses; the only boundary is SAU/GTZC (`sau.rs`). `CMD_SIGN_USEROP` (`nsc/mod.rs:1201-1213`) routes into a 1930-line handler that parses the wire format, verifies the ERC-7730 bundle (`cmd_sign_userop.rs:553`), renders, **and** signs with the master/slot keys inline. The large, attacker-data-driven, **secret-free** surfaces sitting at the same privilege as the key + SAES selector are the **ERC-7730 walker** (`pqsigner-erc7730/` + `tx/display/erc7730/` ≈ **5k LOC** and the *prime* candidate — see below), the **typed-call ABI parser** (`tx/typed_call/parser.rs`, 669 L), and the **EIP-712 Safe / CoW decoders** (`tx/eip712/{safe,cowswap}/`). (The BLS12-381 Groth16 verifier would have been the textbook first candidate, but **ZK Groth16 clear-signing was *removed* in commit `b8a2e59b`** — "retire Groth16 ZK verifier; Aave via native ERC-7730" — so the `secure/src/zk/` module is gone; only dead `ZK_*`/`CMD_CLEAR_SIGN` constants in `proto/src/lib.rs` + "retired" comments remain, and **Aave clear-signing now flows through the native ERC-7730 walker instead** — which is exactly why the walker is now the top surface. SE drivers and raw USB are *not* differentiators — SE is S and OTG is NS on both stacks.) The ERC-7730 walker is also the *most active* attack surface: the C1/C2/C3 commits just added dynamic-field / `FollowOffset` / multi-dynamic-array resolvers (the security-sensitive `head_bounded_body` slot-confusion territory), and two WYSIWYS holes were closed in the same window (duplicate tuple-member names — a **HIGH** — `7c9cf5a2`; `visible:"never"` no-param — `8afb7ec2`). Notably the **SVC vector is unused on the S side (0 uses; NSC rides CMSE SG veneers, the timer rides PendSV)** and the MPU is unused — a clean `unpriv-parser → SVC → priv-signer` escalation vector exists today.

- **Corrected recommendation — defer-with-rationale (not "N/A", not "open a secmon port").**
  1. A **full `secmon` port is declined on principle**: pushing decode/render to NS and signing the digest it returns *imports the blind-digest trust-base fork PQSigner is built to refuse*. This is not a difficulty call.
  2. The **one defensible, scoped increment** is a `secmon`-*lite* **MPU + SVC privilege split inside S** (orthogonal to SAU/GTZC, composes with the no-heap/stack-only model): run the largest attacker-data parsers — the **ERC-7730 walker** first (now ~5k LOC, the most active surface, and where the HIGH dup-name WYSIWYS hole just lived), then the **typed-call ABI parser** and the EIP-712 Safe/CoW decoders — in an **S-unprivileged** MPU region, revalidating their small output (bool + bound fields) on return with the same copy-to-S-stack/TOCTOU discipline already used at the NS boundary, keeping key material + SAES selector + SE-unlock + FI-sign privileged. (The Groth16 verifier would have been the textbook first candidate, but it was removed in `b8a2e59b`; the ERC-7730 walker inherited its role and now also carries the Aave clear-signing traffic.) Effort **L–XL**.
  3. A cheaper MPU **W^X / XN on parser regions** addresses code-injection, **not** key blast-radius — so it is *not* a `secmon` substitute, only a precursor.
  4. **Honest caveat:** PQSigner's S-world is memory-safe `#![no_std]` Rust — the C + MicroPython attack surface `secmon` was built to contain largely does not exist here — so even the MPU-lite split may be **correctly declined in favour of higher-yield audit spend**. The required action is to *record this as deliberately-deferred with the blast-radius argument and the SVC/MPU feasibility on the table*, not to keep waving it off as "small and audited." Reconciles with C-2.

### 1. Residual resolved — HASH-engine per-op fault (the pass's "most worthwhile unevaluated" item)

**Verdict: real but narrow; no headline break; two cheap fixes, one of which collapses into `sca-3`.** Under `hw-sha256` (auto on `stm32u585`), ALL SHA-256 in `sphincs-c10` — keygen, both double-compute sign passes, AND the verify-before-release — routes through the single `pqsigner_sha256_*` engine (`sphincs-c10/src/hash.rs:106-148`). That engine is therefore a single point of trust for the whole FI gate.

- **What `hash.rs` checks:** boot KAT once (`:141-162`, halts on mismatch); BUSY before start (`wait_ready :175-189`); DCIS before reading the digest (`:319-333`). It is NOT a bare write/read driver.
- **What it lacks — and the concrete defect (H-1):** on timeout both `wait_ready` (`:186`) and the DCIS wait (`:331`) just `return`. The DCIS `return` fires **before** the HR-read loop (`:338-356`), so the caller's 32-byte `out` is left untouched — a stale/garbage digest is consumed as "the hash" with no error channel (`debug_log_safe` is a no-op without a debugger). A glitch-induced hang silently degrades to a wrong digest.
- **Blast radius (honest):** a *transient* single-shot glitch is caught by the `ct_eq` double-compare (`crypto.rs:188`) — the other pass, jittered by `wait_random()`, isn't identically corrupted. A *deterministic/reproducible* fault corrupts sign_a, sign_b, and verify identically → passes `ct_eq` AND verify (verify uses the same engine, so it is self-consistent and proves nothing about the engine). That surviving sliver is exactly the Genêt (TCHES 2023) grafting-leak class the double-compute exists to block. Forgery is off the table (the on-chain `SPHINCsC10Asm.sol` verifier uses the real SHA-256 precompile → a device-hash-broken sig reverts on-chain); a *persistent* defect also breaks keygen → dead wallet, caught by KAT/first-sign.
- **STM32U5 `HASH_SR` has NO hardware fault flag** (SVD-confirmed), so the *literal* "per-op fault check" the pass imagined is inert. The realistic closes:
  1. **Independent shuffle seed per double-compute pass (= `sca-3`, now with a second rationale).** This is the change with real teeth against the deterministic-fault seam, not just SCA. See §2 below — it decorrelates the two passes' computation ORDER so a position-triggered deterministic fault hits different WOTS/FORS positions per pass → divergent sigs → caught by `ct_eq`. **Re-elevated from low-med to med.** [work-todo hash-fault-1]
  2. **Fail LOUD on timeout** (H-1) — park the CPU like the KAT-FAIL path or poison `out`; assert FIFO drained + BUSY clear before trusting HR. Catches the stalled/incomplete (DoS) class. [work-todo hash-fault-2]
  3. Optional per-sign KAT (catch latched engine defect between boot and sign) + double-compute keygen pk_root on the provisioning path only. [work-todo hash-fault-3 / keygen-fi-1]
- **Trezor contrast:** `core/embed/sec/hash_processor/stm32u5/hash_processor.c` is a thin ST-HAL wrapper with an **unbounded** busy-wait (`:84`) and **discards every `HAL_StatusTypeDef`** (`:88/100/120/132/146`) — it does LESS per-op fault detection than PQSigner, and it trusts the engine only in the fail-safe *boot* direction (a faulted hash rejects a good image; it can't accept a bad one without a preimage). The pass's implicit "Trezor is the robustness exemplar here" framing is not supported by its code — the value is the internal analysis, not a port.
