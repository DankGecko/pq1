# Fuzz harnesses

Coverage-guided libFuzzer targets for PQSigner's pure-logic parsers.
The proptest sibling is `secure/src/fuzz_props.rs` (always-on, runs
under `cargo test`); this directory adds the coverage-guided variant
called out in `docs/architecture/trezor-comparison.md §2.4`.

This is a **standalone workspace** — `Cargo.toml` at the repo root
excludes `fuzz/` so cargo-fuzz's nightly + sanitizer requirements
don't bleed into the firmware build. You can ignore this directory
entirely unless you're actively fuzzing.

## One-time setup

```bash
cargo install cargo-fuzz       # 0.12+; uses libFuzzer
rustup install nightly         # cargo-fuzz needs nightly for -Z sanitizer
```

## Run a target

From this directory:

```bash
cd fuzz
cargo +nightly fuzz run aa_userop_parse_header
cargo +nightly fuzz run tx_core_rlp_decode_item
cargo +nightly fuzz run tx_core_eip1559_parse
cargo +nightly fuzz run tx_erc20_parse_calldata
cargo +nightly fuzz run tx_erc20_verify_bundle
# Or enumerate the complete current set from the manifest:
make -C .. fuzz-list
```

libFuzzer runs until you `Ctrl-C` or it finds a crash; a crash
produces an artifact under `fuzz/artifacts/<target>/`. Reproduce
locally:

```bash
cargo +nightly fuzz run <target> fuzz/artifacts/<target>/crash-<hex>
```

For CI you typically want a bounded run:

```bash
cargo +nightly fuzz run <target> -- -max_total_time=600    # 10 minutes
```

## Targets, what they exercise, and the proptest cross-check

| Target | Function | Counterpart proptest |
|---|---|---|
| `aa_userop_parse_header` | `pqsigner_aa::userop::parse_header` — the unified SIGN_USEROP wire-format parser CLAUDE.md §"Wire formats" describes | `fuzz_props::aa_userop_parse_header_never_panics` |
| `tx_core_rlp_decode_item` | `pqsigner_tx_core::rlp::decode_item` — foundational RLP decoder | `fuzz_props::rlp_decode_item_never_panics` |
| `tx_core_eip1559_parse` | `pqsigner_tx_core::eip1559::parse` — EIP-1559 envelope decoder | `fuzz_props::eip1559_parse_never_panics` |
| `tx_erc20_parse_calldata` | `pqsigner_tx::erc20::calldata::parse_erc20_calldata` — Solidity-ABI ERC-20 method dispatch | `fuzz_props::parse_erc20_calldata_never_panics` |
| `tx_erc20_verify_bundle` | `pqsigner_tx::erc20::bundle::verify_erc20_bundle` — Merkle-bundle verifier | `fuzz_props::verify_erc20_bundle_never_panics` |
| `apdu_parse_header` | APDU header/length parser above the HID assembler | `apdu_framing::fuzz_props::parse_apdu_header_never_panics` |
| `hid_frame_assembler` | USB-HID report reassembly state machine | `apdu_framing::fuzz_props::hid_frame_random_input_never_panics` |
| `multisend_decode` | Strict Safe MultiSend outer decode plus per-record walk | Kani decoder proofs + `multisend_record_walk_differential` |
| `erc7730_ir_parse` | ERC-7730 IR parser and complete format iterator | Kani IR-parser harnesses |
| `erc7730_verify_bundle` | ERC-7730 Merkle bundle and descriptor verifier | bundle unit tests |
| `erc7730_display_primitives` | Trusted-display row writers and arithmetic boundaries | primitive unit/Kani tests |
| `erc7730_render_dispatch` | Full descriptor parse → format dispatch → page emission | renderer unit tests + component Kani proofs + golden frames |

Every target asserts the same baseline invariant: **the exercised pure logic
terminates in bounded time and returns a well-typed result for any input
slice** — no panic, no OOB, no UB. Inputs reach these parsers/renderers across
the NS→S trust boundary (USB host payload → NSC gateway → TOCTOU-snapshotted
buffer), so any panic here is a direct DoS path from "anyone with a USB cable"
to "secure-world halt."

## Seed corpora

Optional but useful for warming up libFuzzer's coverage map. Four small,
reviewed seeds are checked in: two canonical MultiSend payloads and canonical
ERC-20 `transfer` / `transferFrom` calls. They cross the 4-byte-selector gates
that random bytes are very unlikely to reach. Coverage-guided local and
generated corpora under `fuzz/corpus/` are intentionally ignored; they are
evidence local to that campaign, not reproducible repository inputs. The
root-specific `erc7730_render_dispatch/seed_leaf_*` set is regenerated by
`make fuzz-seed-erc7730-render`; `.clusterfuzzlite/build.sh` performs the same
step for CI. Add a new tracked seed only when it is small, reviewed, and needed
to cross a structural gate.

## What's *not* covered yet

The trezor-comparison §2.4 ask also called out **NSC pointer-
validation** (`secure/src/nsc/ptr_validate.rs`). That module lives
inside `secure::nsc` which is `#[cfg(all(feature = "se050",
not(test)))]`-gated at the crate root, so it isn't reachable from a
`[lib]`-style fuzz harness without first relocating it to a host-
buildable spot (similar refactor to `crate::scp03_logic`). Tracked
as a follow-up; the proptest harness in `fuzz_props.rs` doesn't
cover `ptr_validate` either, so the gap is the same in both
directions.

## When this finds something

1. Reproduce locally with the artifact from `fuzz/artifacts/`.
2. Open the failing input — if it's a 1-block panic, it's almost
   certainly an arithmetic overflow / unchecked slice index.
3. Write a regression `#[test]` in the relevant `fuzz_props.rs`
   `proptest!` block (one specific failing input, not a generator)
   so the fix is permanent.
4. Save the artifact to `fuzz/corpus/<target>/` so libFuzzer never
   regresses on the same shape.

## Running

```sh
make fuzz-all                 # build + run all 12 targets 30s each (FUZZ_TIME=N to change)
make fuzz-rlp-decode-item FUZZ_TIME=120   # one target, longer
make fuzz-list                # list targets
```

On a **nix-based toolchain** the libFuzzer binary can't find `libstdc++` at
runtime (the system one is GLIBC-incompatible with the nix-built cargo-fuzz).
The `make` targets auto-prepend the nix gcc-lib dir via `FUZZ_ENV`; if you run a
target binary by hand, set `LD_LIBRARY_PATH=$(ls -d /nix/store/*gcc-15*-lib/lib)`.
Some hosts expose `llvm-symbolizer` from LLVM 18 without its matching
`libLLVM-18.so.18.1`. That can terminate libFuzzer during its first report and
therefore invalidates the campaign; it is not cosmetic. The Makefile prefers
the versioned `llvm-symbolizer-17`. Enumeration failure, empty target lists,
symbolizer/startup failure, any target's non-zero exit, a target without
reportable output, and any artifact file all make `make fuzz-all` fail.

## Last full campaign (2026-07-13)

All 12 targets completed 30-second campaigns against the existing local
per-target corpora, with **zero artifact files**. The renderer completed
21,470,422 executions at `cov: 108` / `ft: 167`. This is seeded local-corpus
evidence, not a fresh/unseeded coverage claim. The detailed receipt and the
separate catalogue-seeded renderer experiment are recorded in
`docs/security/adversarial-review/findings/clear-signing-2026-07-10.md` and
`docs/erc7730-renderer-fuzzability.md`. A crash drops an artifact under
`fuzz/artifacts/<target>/`; triage it as a real unbounded-path bug or harness
artifact before changing a Kani-proven parser.
